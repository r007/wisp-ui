# Component status

Wisp ports Flutter's Material library, using the Material 3 **Expressive** tokens
(release 38.2.83). The token data has **54 component namespaces**; this table maps
them to components, the Flutter widget to read, and the archetype to copy from
(see the [porting guide](porting-guide.md)).

✅ ported · ⬜ not started

## Next up

Every Material 3 Expressive component that has tokens is ported (the chips, cards and text
fields share one component each). What is left is the foundation below. Beyond the token set,
candidates are anything Flutter has that Material publishes no tokens for.

## Foundation

Built and reused:

| Piece                               | Used by                          | Notes                                                                                                 |
| ----------------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `usePressable`, state layer, ripple | every pressable control          | Button-or-link semantics, disabled handling, toggle state, press ripple                               |
| `useModalDialog`                    | Dialog, NavigationDrawer         | Native `<dialog>` with an exit animation in every browser (`data-closing`), scrim and Escape handling |
| `useMenuNavigation`                 | Menu, FabMenu                    | The menu button keyboard pattern: arrows, Home/End, typeahead, Tab closes, choosing closes            |
| `useWheelScroll`                    | Tabs                             | A vertical mouse wheel scrolls a row that only scrolls sideways; the page scrolls at the ends         |
| `useMediaQuery`                     | TimePicker                       | Whether a media query matches, for a layout a container cannot decide                                 |
| `usePopover`                        | Menu, Tooltip, Snackbar, FabMenu | Native manual popover placed by CSS anchor positioning; script-driven dismissal and exit animation    |
| The list-item contract              | List, Menu                       | One set of private variables an item reads; a container supplies them from its own tokens             |
| `ButtonGroupContext`                | ButtonGroup, SplitButton         | Sizes the Buttons inside and tells a connected group's buttons to draw shared corners                 |
| Snackbar queue                      | Snackbar                         | `SnackbarProvider` and `useSnackbar`                                                                  |

## Expressive features used so far

Springs (fast spatial for shape morphing, fast effects for colour) · shape morph on
press and toggle (buttons, chips, list segments, connected button groups, split
buttons) · five button/icon-button/slider sizes · the Expressive `nav-bar`, `nav-rail`,
`menus` and `chips` tokens · wavy progress indicators · the Expressive slider with its
handle pill · flexible app bars · connected button groups · the emphasised type scale · the Standard/Expressive
motion switch.

Shape morphing is the exact feature-matched algorithm, in `shapes/`.

## Browser support

The components rely on modern CSS (`@layer`, `:has()`, `color-mix()`, `@starting-style`,
anchor positioning, `popover`). The suite runs in Chromium in CI, and in **Firefox** and
**WebKit** (Safari's engine) on request (`WISP_BROWSERS=chromium,firefox,webkit pnpm test`); all
three are green. See "Cross-browser testing" in the
[porting guide](porting-guide.md).
